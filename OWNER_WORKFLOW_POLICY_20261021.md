## Confirmed and implemented

- Cow/Pig fee is exactly PHP95 per animal: Coral15, Delivery25, Ante/post-mortem10, Facility45. Existing canonical fields remain `corralCents`, `deliveryCents`, `inspectionCents`, `facilityCents` for compatibility. No table charge and no weight-based change. Other species are not supported by current animal registration/billing; they need their own approved rates and reviewed support. The explicitly approved version1 schedule is saved locally in `deployment/approved-fees.owner-20261021.proposed.json`; **not written to Firestore**. Later provisioning must read existing state and stop on conflict, propose a higher version if necessary, and never overwrite or recalculate historical invoice snapshots.
- Only Staff with explicit Billing permission issues invoices and records **cash** payments against existing paper official receipt references. Administrator retains municipal reads/oversight, with financial mutation denial in the operations router/store and legacy invoice middleware. Web Add/MarkPaid/MarkUnpaid/Delete controls are hidden. Explicit multi-permission Staff retain their authorized functions. Historical bank-transfer/payment records remain readable; new writes are cash-only. Paper receipt uniqueness and full-payment arithmetic remain; no partial, refund, void or automatic payment inference.
- Invoice due date must equal its server-calculated Manila issue date. Settings returns server-authoritative `invoiceDueDate` and `serverTime`; clients show this date without arbitrary credit-term entry. A midnight conflict requires refresh and explicit resubmission. Audit times remain UTC/server-generated. Historical due dates stay unchanged.
- Current actual measured carcass weight is mandatory before invoice (existing invoice locks prevent later measurement), assignment, dispatch status and fresh tracking publication. Measurement must match current approved animal revision and contain valid measurement/audit fields. Estimate alone and historical measurements cannot satisfy this requirement. Existing exact80% estimates remain distinct; historical reads are preserved without rewriting measurements.
- Only an Inspector assigns active municipal Delivery Staff. The server rereads animal/invoice/vendor scope, current measurement, active vendor and the existing normalized market-stall reservation. Inspector must confirm the canonical current destination. Assignment snapshots market/section/stall plus Inspector/time in audited storage. No freeform or inferred destination, geocoding or coordinates. The existing destination-string limit remains200; an oversized legitimate combined address fails explicitly for review rather than truncation.
- Assignment, dispatch and authorized transit tracking may precede payment. They retain assignee-only status/location permissions, ordered transitions, expected revisions, audits, tracking ordering/rate limits and individual gates. Payment remains independent; shipment/arrival never proves settlement.
- All mutations retain original invoice values and immutable fee snapshots. Operation audits now also include before/after values with actor/time. Existing invoice/animal locks and no-direct-edit/delete protection remain. Financial **correction actions stay unavailable** until permitted cancel/reissue/reversal semantics are decided; no paid total is directly overwritten.

## Coordinated additive API

Existing `workspaceContract: billing_delivery_v1`, invoice reads and `delivery_assignment_v1` stay. Settings adds `invoiceDueDate`, `serverTime`, `canReadAssignmentCandidates` (Inspector, independent of write gate), `canAssignDelivery` (Inspector + delivery gate). Admin canBill/canRecordPayment/canDeliver are false.

Inspector GET `/api/mobile/operations/assignment-candidates?cursor=` returns `{items:[{invoiceId,revision,animalId,animalIdentifier,vendorBusinessId,vendorName}],nextCursor}`. Reads page the municipal invoice register first and filter unassigned rows; empty pages can have continuation. No invoice money, payments, locations or unrelated actors. GET `/delivery-staff?cursor=` pages scoped memberships, returns only active supported Delivery Staff `{uid,fullName?}`; no mailboxes. Query/index prerequisite is default ascending `mobile_memberships.municipalScopeId` plus implicit document ID; actual runtime readiness remains a later read-only check. Existing scoped invoice indexes are reused, not redeployed here.

GET `/invoices/:id/assignment-options` (Inspector only) returns `{invoiceId,revision,animalId,vendorBusinessId,vendorName,destination,marketName,marketSection,stallNumber}` after current measurement/vendor/reservation checks. POST `/invoices/:id/delivery` accepts exactly `{expectedRevision,assigneeUid,destination,destinationConfirmed:true}`; destination is an optimistic-lock comparison of the server-provided canonical string, not editable text. Response is financial-free `{projection:'delivery_assignment_confirmation_v1',invoiceId,revision,assigneeUid,destination,status}`. Other roles cannot assign. Snapshot verification actors stay in protected storage/audits, not Inspector/Delivery projections.

Admin GET `/api/operations/oversight/invoices/:id` returns authorized canonical invoice/fees/balance/payment reference, linked animal inspection/measured weights, assignment and latest authorized tracking with timestamps. It rechecks invoice revision across reads; it is not an accounting snapshot or a location guarantee. Web dashboard links this read-only panel. Refresh updates both panel and matching invoice card; failed sync is visible, locations age honestly, map polling remains separately authorized, and no stale result is called a successful refresh. Mobile writes refresh affected native lists; cross-client Web refresh reads the same IDs/documents, not a second copy.
