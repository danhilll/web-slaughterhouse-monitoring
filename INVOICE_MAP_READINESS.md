## Implemented contract

`GET /api/[mobile/]operations/animals/:id/invoice-preview` is Billing/admin-only and municipal-scoped. It runs a read-only transaction using the same input-validation helper as invoice issuance: approved current animal revision, no invoice/dispatch link or deterministic duplicate, active matching owning business, valid approved fee schedule. Production mode rejects synthetic/unproven fees. Missing fees return503, not substituted amounts. It returns `projection: invoice_preview_v1`, animal `{id,identifier,species,weightGrams,revision,vendorBusinessId,municipalScopeId}`, vendor `{id,name}`, feeSchedule (existing allowlisted version/basis/currency/four integer-centavo components/provenance), `totalCents`, `currency:PHP`. No account credentials, locations or audit actors are included.

Web/native preview validates selected animal, owner, scope and exact total. Web now requires explicit confirmation after itemized preview and an entered due date; POST remains unchanged and rechecks all inputs transactionally. Duplicate protection, immutable fee snapshots, animal locks and invoice audit writes remain. Vendor own-business reads and accurate full-payment balances are tested. Audit history here means preservation of `operation_audit` events; no new Staff audit/actor-read permission or audit browser is introduced.

Text destinations do not imply coordinates. Delivery/MAPCN explicitly distinguish last shared delivery position from destination and current viewing-device position. No geocoding, destination-position storage, device-position overlay or location publication fallback is added. Web refresh clears selected map to prevent reopening a previous selection after an empty/error refresh. Network/no-position states stay honest. MAPCN renderer, bridge, worker, CSP/network restrictions, tracking authorization and location permission mechanics remain unchanged; focused Android checks cover their existing behavior.
